## 二、プロジェクト概要

### 2.1 背景

スタジオ公式サイトが失敗する典型は二つです。一つは CMS 駆動の複数ページサイトにしてしまい、半年で更新が止まり、内容が製品より古くなるパターン。もう一つは技巧的な作品集にしてしまい、ファーストビューがアニメーションで埋まり、訪問者がプロジェクトへの入口を見つけられないパターンです。

### 2.2 解決する課題

訪問者はトップページを開いた瞬間に三つの答えを得るべきです：**誰か、何を作っているか、どこを見るか**。三秒で答えられなければ、そのページは失敗です。

### 2.3 中核の考え方

サイトの責務はたった三つです：

| 責務 | やり方 |
|---|---|
| ブランド認知の確立 | ファーストビューで「星玖工作室 / Ntarstudio / Ntars」の三呼称を対応づける |
| オープンソースへの誘導 | 七枚のカードで正式アドレスへ直結 |
| 情報の正確さ | 未公開・終了済みの情報はページ・キーワード・構造化データのいずれにも出さない |

### 2.4 想定場面

- 小規模な独立スタジオの公式名札ページ；
- 長期安定・ほぼ無保守で運用したい静的サイト；
- 「ビルドなしフロントエンド」の教材サンプル（HTML 一枚でサイトをどう構成するか）。

### 2.5 非目標

やらないことも明確です：

- アカウント、フォーム、Cookie、解析タグ、広告、バックエンド API はありません；
- jQuery / Vue / React / UI コンポーネントライブラリを使わず、Tailwind も Vite / Webpack / Rollup も使いません；
- localStorage への書き込みはしません（唯一の例外は 5.1 節のテーマ解説：意図的に書かない）。

| | |

Android のカスタマイズに必要な操作をすべてブラウザに移しました。ADB プロトコルは Tango で実装し、届けるのは玩机する人がそのまま使える画面と手順です——アプリ管理、ファイル閲覧、ターミナル、画面ミラーリング、ログ、書き換え。合計 152 機能、いずれもリスク階層付きです。

**一読の価値**：いちばん面倒な「環境準備」の層を丸ごと削除しました。従来は Platform-Tools を落とす → PATH を通す → USB ドライバを入れる → udev ルールを書く → 接続 → コマンド、という流れですが、前半五つを「ページを開く → 接続を押す → 機能を押す」に圧縮しています。そして本当に難しかったのは決してコマンド入力ではなく、「設定し終えたのに繋がらない」とき、ケーブルか、ポートか、ドライバか、それとも裏で `adb.exe` がインターフェースを掴んだままなのか、判別できない瞬間でした。

**もう二点**：成果物はすべて静的 `dist/` で、`grep -r "http" dist/` に自前のバックエンドアドレスは一行も出ません——「データは端末から出ない」は約束ではなく検証可能な事実です。加えて全操作にリスク階層を付け、拾ってきたコマンドが何を変え、戻せるのかまで画面に書いています。

- **名称**：単一ページの総索引。
- **価値**：「このスタジオが何を作っているか知るには十のリポジトリを開く必要がある」を解決。
- **実装**：サイトのカード、本文第三章、GitHub プロフィール README が同一リストを同じ状態表現で示します。
- **差異化**：多くの個人ページは公開済みだけを並べるか、情報を各リポジトリの README に分散させています。
- **証拠**：三か所のプロジェクト名・状態・リンクが項目ごとに対応。5.9 節の状態表を参照。

### 見どころ二：依存ゼロ・ビルドなし、保存すれば即反映

- **名称**：ツールチェーンなし。
- **価値**：「半年更新しないと二度とビルドできなくなる」を解決。
- **実装**：`node_modules` も `package.json` もロックファイルもありません。`python3 -m http.server 8000` でローカル確認できます。
- **差異化**：多くの「ミニマルサイト」がなお Vite や Webpack を使い、「テンプレートに入っていたから」と説明します。
- **証拠**：ルートに `package.json` なし。デプロイは「main に push → EdgeOne Pages が自動公開」。

### 見どころ三：テーマはシステム追従、初回フレームで白く光らない

- **名称**：二フレーム固定の初期テーマ。
- **価値**：ダークなシステムでページを開いたときの一瞬の白飛びを解決。
- **実装**：`<head>` で同期実行するインラインスクリプトが `prefers-color-scheme` を読み、結果を `<html data-theme>` に書き込みます。先に `theme-lock` を付けて遷移を抑制し、テーマ確定後に二フレーム連続の `requestAnimationFrame` を経て外します。
- **差異化**：よくある方法は `DOMContentLoaded` を待ってから設定するか、白飛び対策をしません。
- **証拠**：`html:not(.theme-lock)` 下の統一 0.5 秒トランジション規則。

### 見どころ四：カードの光暈がポインタを追う、DOM は触らない

- **名称**：CSS 変数駆動のポインタ光暈。
- **価値**：「ホバー効果がレイアウトリフローを起こす」を解決。
- **実装**：`app.min.js` がカード基準のポインタ座標を `--mouse-x` / `--mouse-y` に書きます。カードの `::before` が `radial-gradient` で追従する光暈を描きます。
- **差異化**：よくある追従光暈は JS で絶対配置要素を動かし、`mousemove` ごとに合成層の再構成を起こします。
- **証拠**：`app.min.js` は座標計算と変数書き込みのみ。

### 見どころ五：ダイアログスクロールの二つの落とし穴を処理

- **名称**：スクロールバー補償と退場方向。
- **価値**：自作ダイアログがほぼ必ず犯す二つのミス——開くとページが右にずれる、閉じるとパネルが隅に「吸い込まれる」——を解決。
- **実装**：開くとき `padding-right` を補ってから `overflow: hidden`。閉じるときは `opacity` の遷移終了を待ち（500ms のフォールバックタイマー付き）、`opacity` のみ遷移して `transform` は触りません。
- **差異化**：`transform` を触るとパネルが変換原点へ移動し、吸い付くように見えます。
- **証拠**：`prefers-reduced-motion` でアニメーションが飛ばされる場合、500ms タイマーが閉じられる唯一の経路です。

## 五、設計詳細と技術的取捨

**本章は本文で唯一サイト自体を扱う部分です。** 意図的に圧縮しています——プロジェクト紹介こそが主眼です。

### 5.1 テーマ：システム追従、手動上書き可、リロードで記憶しない

「星玖工作室出品」をダブルクリックすると手動で反転し、`<meta name="theme-color">` を同期してモバイルのアドレスバーも同色にします。

**手動状態を localStorage に書かないのは意図的です。** 既定の体験はシステム追従であり、スイッチを一つ保存するごとに説明すべき状態が一つ増えます。リロードでシステム設定に戻ります。

### 5.2 ページの五ブロック

上から挨拶、区切り線、プロジェクト、右上の「お問い合わせ」入口、フッター。加えて常駐する四つのオーバーレイ（花火 canvas、軌跡 canvas、背景粒子 canvas、下部装飾）。

ルーターなし、仮想 DOM なし、スクロールはブラウザ標準です。

### 5.3 挨拶の三デバイス帯

| デバイス | 判定 | 表示 |
|---|---|---|
| スマホ | ビューポート < 768px | Hi, I'm **Ntars** |
| タブレット | 768–1180px かつタッチ対応 | 横向きはスタジオモード、縦向きは個人モード |
| デスクトップ | それ以外 | Hi, We're **Ntarstudio** |

タブレット判定は追加で `ontouchstart in window` または `navigator.maxTouchPoints > 0` を要求します。さもないと大きなウィンドウのデスクトップブラウザが誤判定されます。

### 5.4 プロジェクトカード：設定駆動

カードは `PROJECTS` 配列から描画され、七つの項目がそれぞれタイトル・説明・リンク・任意アイコンの四フィールドを持ちます。`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`、間隔 16px で、デスクトップは三列、狭い画面は一列。メディアクエリは不要です。

プロジェクトの状態変更はデータ一行の変更であり、HTML の一ブロック変更ではありません——「カードを直してメタ情報を忘れた」「カード構造が乖離した」という二種類の過去問題を避けます。

### 5.5 スクリプトは一つではなく六ファイル

| ファイル | 責務 |
|---|---|
| `security.js` | 選択・コピー・右クリック・ショートカットを無効化、改竄検知 |
| `app.min.js` | カード光暈：ポインタ座標 → CSS 変数 |
| `anime.js` | anime.js v2.0.2（第三者、MIT、未改変） |
| `firework.js` | 花火粒子 |
| `trail.js` | ポインタ軌跡 |
| `bg.js` | 背景粒子と結線 |

各ファイルは一つのことだけを担い、問題があれば単独で外せます。唯一のハード依存は `firework.js` が `anime.js` に依存する点で、読み込み順は `security → app.min → anime → firework → trail → bg` に固定です。

### 5.6 キャッシュ版番号が最も忘れやすい一手

**`CACHE_NAME` は現在 `ntarstudio-v9`。** プリキャッシュ一覧の資源（CDN 経由の Typed.js を含む）を触ったら必ず版を上げます。さもないと再訪ユーザーは古いキャッシュに留まります。

### 5.7 セキュリティ対策の正直な限界

`security.js` は選択・コピー・切り取り・右クリック・ドラッグ・F12・ソース表示系ショートカットを遮断します。

**はっきり書いておきます：これらの措置は気軽なコピーの敷居を上げるだけで、内容保護にはなりません。** フロントエンドのコードは訪問者から常に見えており、どんなスクリプトでもそれは変えられません。

### 5.8 CSP 許可リスト

| 指令 | 値 |
|---|---|
| `default-src` / `script-src` | `'self'`、インライン、`https://unpkg.com` |
| `img-src` | `'self'` と `data:` |
| `frame-src` / `object-src` | `'none'` |
| `connect-src` | `'self'`（外部 API 呼び出しなし） |

加えて `nosniff`、`X-Frame-Options: DENY`、`referrer: no-referrer`。

### 5.9 三か所同時更新の規律

プロジェクトの状態変化（公開・終了・ドメイン変更）時、次を同時に更新します：

1. `index.html` の `PROJECTS` 配列；
2. 本文第三章「十のプロジェクト」；
3. GitHub プロフィール README `ntars/ntars` のプロジェクト表。

**終了したプロジェクトはどの形でも復活させません**——ページ・キーワード・構造化データのいずれにも出しません。

## 十五、既知の問題と制限

1. **キャッシュ版番号は人手に依存**：`CACHE_NAME` の上げ忘れは再訪ユーザーを古いキャッシュに留め、しかもどこにもエラーが出ません。
2. **手動テーマ状態は非永続**：リロードでシステム設定に戻ります。これは意図的な設計であり欠陥ではありません。
3. **タブレットではタップ切替を無効化**：モードは向きで決まり、手動状態と衝突します。
4. **フロントエンドの内容保護は無効**：`security.js` は敷居を上げるだけです。
5. **Typed.js は CDN 経由**：unpkg に到達できないとタイピング効果は失われますが、他の内容には影響しません。
6. **計画中プロジェクトのカードにはダウンロードできるものがありません**：状態を正直に示す代償であり、計画を実装済みと書かない理由でもあります。
