## 1. 프로젝트 이름과 위치

> **仓库描述 / Description**：`星玖工作室官网与十五个开源项目总索引：一个 HTML、一份样式表、几个原生脚本 | The Ntarstudio official site and an index of fifteen open-source projects, in one HTML file and a stylesheet.`
>
> **话题标签 / Topics**（20 个，仅英文）：`frontend`, `landing-page`, `no-framework`, `personal-website`, `portfolio-site`, `pwa`, `service-worker`, `single-page`, `static-site`, `studio-website`, `vanilla-css`, `vanilla-javascript`, `ntarstudio`, `chinese-website`, `html`, `css`, `javascript`, `dark-mode`, `responsive-design`, `no-dependencies`


**이름**: Apex, 정점을 뜻합니다. 스튜디오 공식 사이트로서 맡는 역할은 「제품」이 아니라 「입구」입니다.

**한 줄 정의**: 의존성 없음, 빌드 없음의 단일 페이지 정적 사이트. 최소한의 코드로 「누구인지, 무엇을 만드는지, 어디를 보면 되는지」를 말합니다.

**세 가지 경계**:

1. **명패이며 전시장이 아닙니다.** 제품 기능을 싣지 않고, 온라인 데모도 하지 않으며, 문서 사이트도 내장하지 않습니다. 방문자가 더 나아갈 링크를 바로 놓습니다.
2. **정적 파일이며 애플리케이션이 아닙니다.** 백엔드도 데이터베이스도 계정 체계도 없습니다. 모든 내용은 `index.html`에 직접 적혀 있고, 한 줄 문구 수정이 곧 한 번의 커밋입니다.
3. **색인이며 정보원이 아닙니다.** 프로젝트의 실제 정보는 각 저장소와 각 사이트에 있습니다. 이 페이지는 집약과 연결만 하고 내용을 중복 보유하지 않습니다.

**왜 이 README가 프로젝트 소개를 중심에 두는가**: 공식 사이트의 「星玖工作室出品」 블록은 열다섯 프로젝트를 모두 나열합니다. 그 목록, 이 문서 3장, GitHub 프로필 README는 같은 원천에서 나옵니다. **스튜디오가 무엇을 만드는지 빠르게 알고 싶은 사람은 이 페이지 한 장이면 충분합니다** — 열다섯 저장소를 열어볼 필요가 없습니다.

## 2. 프로젝트 개요

### 2.1 배경

스튜디오 공식 사이트가 실패하는 전형은 두 가지입니다. 하나는 CMS 기반 다중 페이지 사이트로 만들어 반년 만에 업데이트가 멈추고 내용이 제품보다 낡아지는 경우. 다른 하나는 기교적인 작품집으로 만들어 첫 화면이 애니메이션으로 가득 차 방문자가 프로젝트 입구를 찾지 못하는 경우입니다.

### 2.2 해결하는 문제

방문자는 첫 화면을 열자마자 세 가지 답을 얻어야 합니다: **누구인지, 무엇을 만드는지, 어디를 보면 되는지**. 3초 안에 답하지 못하면 그 페이지는 실패입니다.

### 2.3 핵심 접근

사이트의 책무는 딱 셋입니다:

| 책무 | 방법 |
|---|---|
| 브랜드 인지 확립 | 첫 화면에서 「星玖工作室 / Ntarstudio / Ntars」 세 호칭을 대응시킴 |
| 오픈소스로 유도 | 카드 열 장이 정식 주소로 직결 |
| 정보의 정확성 | 미공개·종료된 정보는 페이지·키워드·구조화 데이터 어디에도 넣지 않음 |

### 2.4 적용 장면

- 소규모 독립 스튜디오의 공식 명패 페이지;
- 장기 안정, 거의 무보수로 운영하려는 정적 사이트;
- 「빌드 없는 프론트엔드」 교재 샘플(HTML 한 장으로 사이트를 어떻게 구성하는가).

### 2.5 비목표

하지 않는 일도 분명합니다:

- 계정, 폼, 쿠키, 분석 태그, 광고, 백엔드 API가 없습니다;
- jQuery / Vue / React / UI 컴포넌트 라이브러리를 쓰지 않고, Tailwind도 Vite / Webpack / Rollup도 쓰지 않습니다;
- localStorage에 쓰지 않습니다(유일한 예외는 5.1절 테마 설명: 의도적으로 쓰지 않음).

**볼 만한 이유**: README의 20장, 저장소 이름, 설명과 토픽 설정 같은 구두 약속을 검증 가능한 파일과 명령으로 바꿉니다. 이번 열다섯 저장소의 문서 정합도 이 규범을 유일한 기준으로 삼았습니다.

**볼 만한 이유**: 「OS 설치 후 첫 주에 무엇을 쓰는가」에서 도구 목록을 역산하고, 만능 소프트웨어로 키우지 않고 계층으로 보안 경계를 고정합니다.

| TapMC | 골격 단계 | 경로가 통했고 Java 측 84개 테스트와 Dart 측 21개 사례 통과. 배포판 없음 |
| Desop | 빌드 가능한 MVP | `0.2.0`: Python + PySide6 사용자 모드 구현이 빌드·실행됨, 77개 테스트 통과, Windows 11 가상 머신 인수 검사 8/8 PASS. 물리 머신 인수 검사 미완료；데스크톱 위젯은 설정 항목만 있고 화면 미구현 |

**설계 단계 프로젝트도 카드에 싣는 이유**: 사이트는 스튜디오의 명패이며 「이미 완성한 것」만이 아니라 「지금 만드는 것」을 보여 줍니다. 상태를 분명히 적으면 충분하고, 방문자는 「설계 단계」「골격 단계」를 보고 내려받을 것이 없다는 걸 압니다 — 숨기는 것보다 정직합니다.

## 4. 핵심 특성

### 하이라이트 1: 열다섯 프로젝트를 한 페이지에서, 세 곳이 같은 원천

- **이름**: 단일 페이지 총 색인.
- **가치**: 「이 스튜디오가 무엇을 만드는지 알려면 열다섯 저장소를 열어야 한다」를 해결.
- **구현**: 사이트 카드, 이 문서 3장, GitHub 프로필 README가 같은 목록을 같은 상태 표현으로 보여줍니다.
- **차별화**: 많은 개인 페이지는 공개된 것만 나열하거나, 정보를 각 저장소 README에 흩어 놓습니다.
- **증거**: 세 곳의 프로젝트 이름·상태·링크가 항목별로 대응. 3.2절 상태표 참조.

### 하이라이트 2: 의존성 없음, 빌드 없음, 저장하면 즉시 반영

- **이름**: 툴체인 없음.
- **가치**: 「반년 업데이트하지 않으면 다시는 빌드할 수 없다」를 해결.
- **구현**: `node_modules`도 `package.json`도 잠금 파일도 없습니다. `python3 -m http.server 8000`으로 로컬 확인이 됩니다.
- **차별화**: 많은 「미니멀 사이트」가 여전히 Vite나 Webpack을 쓰며 「템플릿에 원래 있어서」라고 설명합니다.
- **증거**: 루트에 `package.json` 없음. 배포는 「main에 push → EdgeOne Pages 자동 공개」.

### 하이라이트 3: 테마는 시스템 추종, 첫 프레임에 하얗게 번쩍이지 않음

- **이름**: 두 프레임 고정 초기 테마.
- **가치**: 다크 시스템에서 페이지를 열 때의 순간적 흰 번쩍임을 해결.
- **구현**: `<head>`에서 동기 실행되는 인라인 스크립트가 `prefers-color-scheme`을 읽고 결과를 `<html data-theme>`에 씁니다. 먼저 `theme-lock`을 붙여 전환을 억제하고, 테마 확정 후 두 프레임 연속 `requestAnimationFrame`을 거쳐 뗍니다.
- **차별화**: 흔한 방법은 `DOMContentLoaded`를 기다렸다가 설정하거나, 번쩍임 대책을 하지 않습니다.
- **증거**: `html:not(.theme-lock)` 아래의 통일 0.5초 전환 규칙.

### 하이라이트 4: 카드 광륜이 포인터를 따라가되 DOM은 건드리지 않음

- **이름**: CSS 변수 기반 포인터 광륜.
- **가치**: 「호버 효과가 레이아웃 리플로를 일으킨다」를 해결.
- **구현**: `app.min.js`가 카드 기준 포인터 좌표를 `--mouse-x` / `--mouse-y`에 씁니다. 카드의 `::before`가 `radial-gradient`로 따라오는 광륜을 그립니다.
- **차별화**: 흔한 따라오는 광륜은 JS로 절대 배치 요소를 움직여 `mousemove`마다 합성층 재구성을 일으킵니다.
- **증거**: `app.min.js`는 좌표 계산과 변수 쓰기만 합니다.

### 하이라이트 5: 다이얼로그 스크롤의 두 함정을 모두 처리

- **이름**: 스크롤바 보상과 퇴장 방향.
- **가치**: 직접 만든 다이얼로그가 거의 반드시 저지르는 두 실수 — 열면 페이지가 오른쪽으로 밀리는 것, 닫으면 패널이 구석으로 「빨려드는」 것 — 을 해결.
- **구현**: 열 때 `padding-right`를 보상한 뒤 `overflow: hidden`. 닫을 때는 `opacity` 전환이 끝나기를 기다려(500ms 폴백 타이머 포함) `opacity`만 전환하고 `transform`은 건드리지 않습니다.
- **차별화**: `transform`을 건드리면 패널이 변환 원점으로 이동해 빨려드는 것처럼 보입니다.
- **증거**: `prefers-reduced-motion`에서 애니메이션이 생략되는 경우, 500ms 타이머가 닫을 수 있는 유일한 경로입니다.

## 5. 설계 세부 사항과 기술적 트레이드오프

**이 장은 이 문서에서 사이트 자체를 다루는 유일한 부분입니다.** 의도적으로 압축했습니다 — 프로젝트 소개가 본령입니다.

### 5.1 테마: 시스템 추종, 수동 덮어쓰기 가능, 새로고침하면 기억하지 않음

「星玖工作室出品」을 더블클릭하면 수동으로 반전되고 `<meta name="theme-color">`를 동기화해 모바일 주소창도 같은 색이 됩니다.

**수동 상태를 localStorage에 쓰지 않는 것은 의도적입니다.** 기본 경험은 시스템 추종이며, 스위치를 하나 저장할 때마다 설명해야 할 상태가 하나 늘어납니다. 새로고침하면 시스템 설정으로 돌아갑니다.

### 5.2 페이지 다섯 블록

위에서부터 인사, 구분선, 프로젝트, 우상단 「문의하기」 입구, 푸터. 여기에 상주하는 네 오버레이(불꽃놀이 canvas, 궤적 canvas, 배경 입자 canvas, 하단 장식).

라우터 없음, 가상 DOM 없음, 스크롤은 브라우저 기본입니다.

### 5.3 인사의 세 기기 대역

| 기기 | 판정 | 표시 |
|---|---|---|
| 폰 | 뷰포트 < 768px | Hi, I'm **Ntars** |
| 태블릿 | 768–1180px 이고 터치 지원 | 가로는 스튜디오 모드, 세로는 개인 모드 |
| 데스크톱 | 그 외 | Hi, We're **Ntarstudio** |

태블릿 판정은 추가로 `ontouchstart in window` 또는 `navigator.maxTouchPoints > 0`을 요구합니다. 그렇지 않으면 큰 창의 데스크톱 브라우저가 오판됩니다.

### 5.4 프로젝트 카드: 설정 기반

카드는 `PROJECTS` 배열에서 렌더링되며, 일곱 항목이 각각 제목·설명·링크·선택적 아이콘 네 필드를 가집니다. `grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`, 간격 16px로 데스크톱은 세 열, 좁은 화면은 한 열. 미디어 쿼리가 필요 없습니다.

프로젝트 상태 변경은 데이터 한 줄 변경이며 HTML 한 블록 변경이 아닙니다 — 「카드를 고치고 메타 정보를 잊었다」, 「카드 구조가 어긋났다」 두 가지 과거 문제를 피합니다.

### 5.5 스크립트는 하나가 아니라 여섯 파일

| 파일 | 책무 |
|---|---|
| `security.js` | 선택·복사·우클릭·단축키 차단, 변조 감지 |
| `app.min.js` | 카드 광륜: 포인터 좌표 → CSS 변수 |
| `anime.js` | anime.js v2.0.2(제3자, MIT, 미수정) |
| `firework.js` | 불꽃놀이 입자 |
| `trail.js` | 포인터 궤적 |
| `bg.js` | 배경 입자와 연결선 |

각 파일은 한 가지 일만 맡고 문제가 있으면 단독으로 뺄 수 있습니다. 유일한 하드 의존은 `firework.js`가 `anime.js`에 의존하는 점이며, 로드 순서는 `security → app.min → anime → firework → trail → bg`로 고정입니다.

### 5.6 캐시 버전 번호가 가장 잊기 쉬운 한 수

**`CACHE_NAME`은 현재 `ntarstudio-v12`.** 프리캐시 목록의 자원(CDN 경유 Typed.js 포함)을 건드리면 반드시 버전을 올립니다. 그렇지 않으면 재방문 사용자가 오래된 캐시에 머뭅니다.

### 5.7 보안 조치의 정직한 한계

`security.js`는 선택·복사·잘라내기·우클릭·드래그·F12·소스 보기 계열 단축키를 차단합니다.

**분명히 적습니다: 이 조치들은 손쉬운 복사의 문턱을 높일 뿐 내용 보호가 되지 않습니다.** 프론트엔드 코드는 방문자에게 항상 보이며, 어떤 스크립트도 그것을 바꾸지 못합니다.

### 5.8 CSP 허용 목록

| 지시문 | 값 |
|---|---|
| `default-src` / `script-src` | `'self'`, 인라인, `https://unpkg.com` |
| `img-src` | `'self'`와 `data:` |
| `frame-src` / `object-src` | `'none'` |
| `connect-src` | `'self'`(외부 API 호출 없음) |

추가로 `nosniff`, `X-Frame-Options: DENY`, `referrer: no-referrer`.

### 5.9 세 곳 동시 수정의 규율

프로젝트 상태 변화(공개·종료·도메인 변경) 시 다음을 동시에 갱신합니다:

1. `index.html`의 `PROJECTS` 배열;
2. 이 문서 3장 「열다섯 프로젝트」;
3. GitHub 프로필 README `ntars/ntars`의 프로젝트 표.

**종료된 프로젝트는 어떤 형태로도 되살리지 않습니다** — 페이지·키워드·구조화 데이터 어디에도 넣지 않습니다.

| CSP | 허용 목록 선언, `object-src` / `frame-src`는 `'none'` |
| 클릭재킹 | `X-Frame-Options: DENY` |
| 리퍼러 누출 | `referrer: no-referrer` |

**프론트엔드 내용 보호에 대한 정직한 설명**: `security.js`는 손쉬운 복사의 문턱을 높일 뿐 내용 보호가 되지 않습니다.

## 15. 알려진 문제와 제한

1. **캐시 버전 번호는 사람에 의존**: `CACHE_NAME`을 올리지 않으면 재방문 사용자가 오래된 캐시에 머물고, 어디에도 오류가 나지 않습니다.
2. **수동 테마 상태는 비영속**: 새로고침하면 시스템 설정으로 돌아갑니다. 의도적 설계이며 결함이 아닙니다.
3. **태블릿에서는 탭 전환 비활성**: 모드는 방향으로 결정되며 수동 상태와 충돌합니다.
4. **프론트엔드 내용 보호는 무효**: `security.js`는 문턱만 높입니다.
5. **Typed.js는 CDN 경유**: unpkg에 닿지 못하면 타이핑 효과가 사라지지만 나머지 내용에는 영향이 없습니다.
6. **미출시 프로젝트 카드에는 내려받을 것이 없음**: 상태를 정직하게 적는 대가이며, 계획을 구현된 것으로 쓰지 않는 이유이기도 합니다.

## 17. 향후 로드맵

1. **캐시 버전 자동화**: 손으로 쓰는 `CACHE_NAME`을 빌드 시 자원 해시로 교체.
2. **카드 아이콘**: 열다섯 프로젝트 아이콘이 준비되면 마운트. 현재 모두 `icon: null`.
3. **접근성 감사**: `role`, `tabindex`, `aria-*`는 있으나 완전한 키보드 주행과 스크린리더 테스트는 미실시.
4. **제3자 의존 축소**: Typed.js는 약 40줄 네이티브 코드로 대체 가능.
5. **OG 미리보기 이미지**: 현재 `og:image`가 없어 SNS 공유 시 썸네일이 나오지 않습니다.
