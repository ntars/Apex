# Apex

**Официальный сайт Ntarstudio (星玖工作室) — и указатель тринадцати проектов.**

> **У этого репозитория две роли**: он содержит исходники сайта студии (один HTML-файл, одна таблица стилей, несколько нативных скриптов) и одновременно служит **указателем тринадцати проектов**. Этот документ посвящён второй роли: что представляет собой каждый проект, на каком он этапе и куда смотреть. Реализация самого сайта сжата в главу 5 и намеренно коротка.

## 1. Название и позиционирование

> **仓库描述 / Description**：`星玖工作室官网与十五个开源项目总索引：一个 HTML、一份样式表、几个原生脚本 | The Ntarstudio official site and an index of fifteen open-source projects, in one HTML file and a stylesheet.`
>
> **话题标签 / Topics**（20 个，仅英文）：`frontend`, `landing-page`, `no-framework`, `personal-website`, `portfolio-site`, `pwa`, `service-worker`, `single-page`, `static-site`, `studio-website`, `vanilla-css`, `vanilla-javascript`, `ntarstudio`, `chinese-website`, `html`, `css`, `javascript`, `dark-mode`, `responsive-design`, `no-dependencies`


**Название**: Apex, «вершина». Как официальный сайт студии он играет роль входа, а не продукта.

**Одной строкой**: статический одностраничный сайт без зависимостей и без сборки, который минимальным кодом отвечает на три вопроса — кто это, что строится, куда смотреть.

**Три границы**:

1. **Это вывеска, а не выставочный зал.** Никаких продуктовых функций, онлайн-демо или встроенной документации. Посетитель идёт дальше по прямым ссылкам на проекты.
2. **Это статические файлы, а не приложение.** Нет серверной части, базы данных, учётных записей. Весь контент записан в `index.html`; изменить строку текста — это один коммит.
3. **Это указатель, а не источник контента.** Реальная информация проекта живёт в его собственном репозитории и на его сайте. Эта страница обобщает и ссылается, но не дублирует.

**Почему README сосредоточен на проектах**: раздел «星玖工作室出品» на главной странице перечисляет все пятнадцать проектов. Этот список, глава 3 настоящего документа и README профиля GitHub — три отображения одного источника. **Тому, кто хочет быстро понять, что строит студия, достаточно этой страницы** — открывать пятнадцать репозиториев не нужно.

## 2. Обзор

### 2.1 Предпосылки

Сайты студий проваливаются двумя способами. Либо превращаются в многостраничные сайты на CMS, которые через полгода перестают обновляться и оказываются старее продуктов. Либо становятся показными портфолио, где первый экран забит анимацией, а посетитель не может найти ссылки на проекты.

### 2.2 Решаемые проблемы

Посетитель должен получить три ответа сразу: **кто это, что строится, куда смотреть**. Если страница отвечает дольше трёх секунд, она провалилась.

### 2.3 Ключевой подход

У сайта ровно три обязанности:

| Обязанность | Как реализовано |
|---|---|
| Утвердить идентичность бренда | Первый экран связывает 星玖工作室 / Ntarstudio / Ntars |
| Направить к открытому коду | Шесть карточек ведут прямо на канонические адреса |
| Говорить правду | Неопубликованная и снятая информация не появляется ни на странице, ни в ключевых словах, ни в структурированных данных |

### 2.4 Сценарии применения

- Официальная вывеска небольшой независимой студии;
- Статический сайт, которому нужна долгая стабильность и почти нулевое обслуживание;
- Учебный образец фронтенда без сборки.

### 2.5 Не-цели

- Никаких учётных записей, форм, cookie, аналитики, рекламы и серверных API;
- Без jQuery / Vue / React / библиотек UI-компонентов, без Tailwind, без Vite / Webpack / Rollup;
- Никаких записей в `localStorage` (единственное исключение разобрано в 5.1: состояние темы намеренно не сохраняется).

#### Serica (行简) · Спецификация заморожена, реализация остановлена на лексере

| | |
|---|---|
| Что это | Язык программирования для приложений с синхронизацией между устройствами: всё на китайском, исходники `.serica`, команда `serica`, на выходе — нативные исполняемые файлы |
| Стек | Go (загрузочный компилятор stage0) · путь самохостинга · прямая запись Mach-O |
| Версия | Спецификация v3.1 заморожена; реализация загрузчика остановлена на лексере и `check`: генерация IR (M3) и кода (M4) не реализованы, исполняемый файл пока получить нельзя |
| Объём | 1928 строк загрузчика при пределе 5000, с построчной таблицей атрибуции; после самохостинга каталог загрузчика удаляется |
| Лицензия | Apache-2.0 |
| Платформы | Проверено только на macOS arm64 |
| Репозиторий | <https://github.com/ntars/Serica> |

По замыслу загрузочный компилятор не генерирует C и не вызывает ни LLVM, ни ассемблер, ни компоновщик: он сам пишет Mach-O. Китайская пунктуация — грамматика лексического уровня, а не типографика; диагностика показывает и колонку кодовых точек, и отображаемую колонку (`строка 3, колонка 38 (ячейка 55)`). **Это проектные цели, а не текущие возможности**: в репозитории работают только лексер и команда `check`; `ir` возвращает «генератор IR не реализован (M3)», `build` — «генератор кода не реализован (M4)», поэтому исполняемый файл получить нельзя, и язык **непригоден для производственного ПО**.

**Почему стоит посмотреть**: «китайский — это не только переведённые ключевые слова» превращено в проверяемые ограничения — предел 5000 строк загрузчика, построчная таблица атрибуции, удаление загрузчика после самохостинга и тип результата, который будет подтверждаться одной командой `file`.

## 4. Ключевые характеристики

### Достоинство 1: пятнадцать проектов на одной странице, три источника синхронны

- **Название**: единый указатель.
- **Ценность**: решает «чтобы узнать, что строит студия, нужно открыть шесть репозиториев».
- **Реализация**: карточки сайта, глава 3 этого документа и README профиля GitHub перечисляют один и тот же набор с одинаковыми формулировками статуса.
- **Отличие**: большинство личных страниц перечисляют только выпущенное или разбрасывают информацию по README репозиториев.
- **Доказательство**: три списка совпадают постатейно; см. таблицу статусов в 3.2.

### Достоинство 2: ноль зависимостей, ноль сборки, сохранил и обновил

- **Название**: без инструментальной цепочки.
- **Ценность**: решает «через полгода без изменений сборка перестаёт работать».
- **Реализация**: нет `node_modules`, нет `package.json`, нет lock-файла. `python3 -m http.server 8000` достаточно для локального просмотра.
- **Отличие**: большинство «минимальных сайтов» всё ещё используют Vite или Webpack под предлогом «в шаблоне уже было».
- **Доказательство**: в корне нет `package.json`; развёртывание — «push main → EdgeOne Pages публикует автоматически».

### Достоинство 3: тема следует системе, без белой вспышки на первом кадре

- **Название**: тема, зафиксированная за два кадра.
- **Ценность**: решает белую вспышку при открытии страницы в тёмной системе.
- **Реализация**: синхронный встроенный скрипт в `<head>` читает `prefers-color-scheme` и записывает результат в `<html data-theme>`; сначала добавляет `theme-lock`, подавляющий переходы, затем снимает его через два последовательных кадра `requestAnimationFrame` после стабилизации темы.
- **Отличие**: обычная практика задаёт тему на `DOMContentLoaded` или вовсе не предотвращает вспышку.
- **Доказательство**: единое правило перехода 0,5 с под `html:not(.theme-lock)`.

### Достоинство 4: свечение карточек следует за указателем, не трогая DOM

- **Название**: свечение на CSS-переменных.
- **Ценность**: решает «эффекты наведения вызывают перекомпоновку».
- **Реализация**: `app.min.js` вычисляет координаты указателя относительно карточки и пишет их в `--mouse-x` / `--mouse-y`; `::before` карточки рисует свечение через `radial-gradient`.
- **Отличие**: распространённый подход двигает абсолютно позиционированный элемент на каждый `mousemove`, вызывая перекомпоновку слоёв.
- **Доказательство**: `app.min.js` только вычисляет координаты и пишет переменные.

### Достоинство 5: обе ловушки прокрутки диалога обработаны

- **Название**: компенсация полосы прокрутки и направление ухода.
- **Ценность**: решает две ошибки, которые допускает почти любой самодельный диалог — страница сдвигается вправо при открытии, панель «втягивается» в угол при закрытии.
- **Реализация**: при открытии добавить `padding-right`, затем `overflow: hidden`; при закрытии дождаться конца перехода `opacity` (с резервным таймером 500 мс) и только потом восстановить прокрутку, анимируя только `opacity` и не трогая `transform`.
- **Отличие**: изменение `transform` двигает панель к началу преобразования, что читается как примагничивание.
- **Доказательство**: при `prefers-reduced-motion` анимация пропускается, и таймер 500 мс остаётся единственным путём, закрывающим диалог.

## 5. Детали дизайна и технические компромиссы

**Это единственная глава о самом сайте.** Она намеренно сжата — главное здесь проекты.

### 5.1 Тема: следует системе, переопределяется вручную, не запоминается

Двойной щелчок по «星玖工作室出品» переключает тему вручную и синхронизирует `<meta name="theme-color">`, чтобы адресная строка на мобильном совпадала.

**Ручное состояние намеренно не пишется в `localStorage`.** Поведение по умолчанию следует системе; каждый сохранённый переключатель — ещё одно состояние, которое нужно объяснять. Перезагрузка возвращает к системной настройке.

### 5.2 Пять блоков страницы

Сверху вниз: приветствие, разделитель, проекты, вход «связаться» справа вверху, подвал. Плюс четыре постоянных слоя наложения (canvas фейерверка, canvas следа, canvas фоновых частиц, нижнее украшение).

Нет роутера, нет виртуального DOM; прокрутка нативная.

### 5.3 Три диапазона устройств в приветствии

| Устройство | Определение | Отображение |
|---|---|---|
| Телефон | Вьюпорт < 768 px | Hi, I'm **Ntars** |
| Планшет | 768–1180 px с поддержкой касаний | Режим студии в альбомной ориентации, личный в портретной |
| Настольный | Остальное | Hi, We're **Ntarstudio** |

Определение планшета дополнительно требует `ontouchstart in window` или `navigator.maxTouchPoints > 0`, иначе большое окно настольного браузера будет ошибочно принято за планшет.

### 5.4 Карточки проектов: управляются конфигурацией

Карточки строятся из массива `PROJECTS`, каждая запись содержит заголовок, описание, ссылку и необязательную иконку. `grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))` с промежутком 16 px даёт три колонки на настольном экране и одну на узком, без медиазапросов.

Изменение статуса проекта — это изменение одной строки данных, а не блока HTML, что исключает «поменял карточку, забыл метаданные» и «карточки структурно разошлись».

### 5.5 Шесть скриптов вместо одного

| Файл | Обязанность |
|---|---|
| `security.js` | Отключает выделение/копирование/правый клик/горячие клавиши; обнаружение подмены |
| `app.min.js` | Свечение карточек: координаты указателя → CSS-переменные |
| `anime.js` | anime.js v2.0.2 (сторонний, MIT, без изменений) |
| `firework.js` | Частицы фейерверка |
| `trail.js` | След указателя |
| `bg.js` | Фоновые частицы и связи |

Каждый файл делает одно дело и может быть удалён отдельно. Единственная жёсткая зависимость — `firework.js` от `anime.js`, поэтому порядок загрузки фиксирован: `security → app.min → anime → firework → trail → bg`.

### 5.6 Номер версии кэша — самый легко забываемый шаг

**`CACHE_NAME` сейчас равен `ntarstudio-v12`.** Любое изменение в списке предварительного кэша — включая Typed.js с CDN — требует повышения версии, иначе вернувшиеся посетители останутся на старом кэше.

### 5.7 Честные границы мер безопасности

`security.js` перехватывает выделение, копирование, вырезание, правый клик, перетаскивание, F12 и сочетания для просмотра исходного кода.

**Чтобы было ясно: эти меры лишь поднимают порог случайного копирования и не защищают контент.** Фронтенд-код всегда виден посетителю, и никакой скрипт это не изменит.

### 5.8 Белый список CSP

| Директива | Значение |
|---|---|
| `default-src` / `script-src` | `'self'`, встроенный, `https://unpkg.com` |
| `img-src` | `'self'` и `data:` |
| `frame-src` / `object-src` | `'none'` |
| `connect-src` | `'self'` (внешних API-запросов нет) |

Плюс `nosniff`, `X-Frame-Options: DENY` и `referrer: no-referrer`.

### 5.9 Дисциплина трёх мест

При изменении статуса проекта (выпуск, снятие, смена домена) три места обновляются одновременно:

1. Массив `PROJECTS` в `index.html`;
2. Глава 3 настоящего документа;
3. Таблица проектов в README профиля GitHub `ntars/ntars`.

**Снятые проекты не возвращаются ни в каком виде** — ни на странице, ни в ключевых словах, ни в структурированных данных.

## 15. Известные проблемы и ограничения

1. **Версия кэша зависит от человека**: забыть повысить `CACHE_NAME` — значит оставить вернувшихся посетителей на старом кэше, причём нигде не возникнет ошибки.
2. **Ручное состояние темы не сохраняется**: перезагрузка возвращает к системной настройке — так задумано.
3. **На планшете переключение касанием отключено**: режим определяется ориентацией.
4. **Защита фронтенд-контента не работает**: `security.js` только поднимает порог.
5. **Typed.js идёт с CDN**: если unpkg недоступен, эффект печати пропадает, остальной контент не страдает.
6. **У карточек невыпущенных проектов нечего скачивать**: цена честного указания статуса — и причина, по которой ничего запланированное не описывается как готовое.

## 17. План развития

1. **Автоматизировать версию кэша**: заменить ручной `CACHE_NAME` хешем ресурсов на этапе сборки.
2. **Иконки карточек**: подключить иконки шести проектов, когда они появятся; сейчас у всех `icon: null`.
3. **Аудит доступности**: `role`, `tabindex` и `aria-*` присутствуют, но полный проход с клавиатуры и тест скринридером не проводились.
4. **Сократить сторонние зависимости**: Typed.js достаточно прост, чтобы заменить его примерно сорока строками нативного кода.
5. **Изображение предпросмотра Open Graph**: сейчас `og:image` отсутствует.

## 18. Участие в разработке

### 18.1 Самопроверка перед изменениями

1. Заголовки, описания и ссылки шести карточек соответствуют реальному статусу проектов;
2. `description`, `keywords`, `og:*`, JSON-LD и `canonical` синхронизированы с текстом;
3. Если изменён предкэшируемый ресурс, `CACHE_NAME` повышен;
4. Проверены обе темы — светлая и тёмная;
5. Нет обрезки и переполнения на ширинах телефона, планшета и настольного экрана;
6. Фон не прокручивается при открытом диалоге, позиция не прыгает после закрытия;
7. **Изменение статуса вносится в три места** (массив `PROJECTS`, глава 3 этого документа, README профиля GitHub).

### 18.2 Дисциплина выпуска

- После любого изменения контента проверять `CACHE_NAME`;
- При изменении статуса проекта одновременно обновлять карточку, метаданные и таблицу статусов;
- Снятые проекты не должны возвращаться ни на страницу, ни в ключевые слова, ни в структурированные данные;
- Перед добавлением стороннего компонента подтвердить совместимость лицензий и зарегистрировать его в `NOTICE`, затем коммитить.
